# 建築保護付きの木材収集

木材の探索・伐採・回収・帰還・収納を一つの有限作業として実行します。伐採範囲の手動指定は不要です。移動には自前の局所探索と基本操作を使い、pathfinderへ木材収集の経路を委譲しません。周辺情報はMinecraftのブロックAPI由来であり、画像による視覚認識が実装されたという意味ではありません。

## 利用前の準備
1. NodeとAgentBridgeを同じ対応版へ更新します。実サーバーの再起動は運用者が判断してください。
2. 非公開の環境設定に `WOOD_OWNER` を設定します。Minecraft上の担当プレイヤー名との完全一致です。既定は空欄（無効）。既存の `BRIDGE_URL` と `BRIDGE_API_KEY`、WorldGuardの正常な照会も必要です。
3. Botを拠点の安全な床へ連れてきて、4ブロック以内の**単独の通常チェスト**を登録します。ダブルチェスト・トラップチェスト・未登録チェストは利用しません。

| チャット | 動作 |
| --- | --- |
| `!wood base x y z` | 現在のBot位置を帰還先、指定したチェストを収納先として記録 |
| `!wood collect 16` | 最大16個の原木を目標に探索・収集・帰還収納（1〜64） |
| `木材を集めて` | 16個を目標に開始 |
| `!wood status` | 現在の段階と未完了記録を確認 |
| `!wood stop` | 移動・掘削を停止。収集物は保持 |
| `!wood return` | 未完了作業の帰還と残りの収納だけを再試行 |
| `!wood reset confirm` | 所持品を手動確認した後に作業記録だけを解除。アイテムは収納・破棄しない |

これは専用の明示コマンドです。認識したコマンドをPythonのLLMへ重複転送しません。他の通常チャットは既存経路を維持します。作業中の別の移動・採掘・装備変更命令はbusyで拒否します。チャット名はMinecraftサーバーの本人識別に依存するため、offline-modeサーバーを不特定の利用者へ公開してはいけません。

## 木と建築の区別
初期対応は、**このサーバー起動中にStructureGrowEventで成長を確認した、3〜6原木が一直線に並ぶ小型のオーク・シラカバ・トウヒ**です。自然成長と骨粉による成長を含みます。根元の土・葉・周囲の人工物・WorldGuard領域・全対象ブロックの一致を確認します。natural由来であることと伐採許可は別々に確認します。

- 導入前の木、新規地形生成の木、再起動前の木、大木・枝分かれした木は由来不明または対応外として伐採しません。苗木から成長させた対象で利用できます。探索しても確認済みの木が見つからない場合があります。
- 近くへのブロック設置、他者の破壊、ピストン、爆発で成長証跡を失効させます。周囲に別の原木、人工材、persistentな葉、保護領域があれば拒否します。未ロード・照会失敗も許可へ変換しません。
- 伐採前のHTTP確認だけでなく、PaperのBlockBreakEventでも一回限りの許可・期限・現在地形を再確認します。上から順に、届いて見える原木だけを掘ります。登るための足場設置や葉の一括破壊はしません。
- 古いCoreProtect一括照会は、照会失敗と履歴なしを区別できないため、自然由来を肯定する根拠に利用しません。今回の肯定証跡はPaperの成長イベントです。

履歴はメモリ上の上限付き記録です。再起動で忘れた対象は安全側に拒否します。WorldEdit等のイベントを経由しない編集・rollback・他プラグインの直接ブロック変更を監視し切る保証はありません。そのような操作と収集を並行させず、終了後に再起動して古い証跡を捨ててください。自然木を模した建築や自然素材だけの構造物を一般に完全判別する機能ではありません。

## 探索・帰還・収納の上限
登録拠点を中心に6/12/18ブロックの4方向を自動探索し、各地点で観測済みの10ブロック以内の候補を調べます。これはユーザー指定領域ではなく、帰還可能性と時間のための初期探索予算です。探索は約3分、一回の移動は最大25秒、帰還全体は最大3分で制限します。複雑な高低差、広域森林、全地形の到達を保証しません。停止・health/food低下・空き不足・目標到達で探索を切り上げます。木を途中で切り残す目標数になる場合は、その木を開始しません。

出発前に登録チェストへのアクセスと空き、開始時所持品を確認します。通過位置を記録し、帰還ではそれを逆順に使いながら毎回地形を再観測します。帰路が変われば停止します。拾得を確認した原木・苗木・棒・リンゴのうち、開始時より増えた数量だけを格納し、装備や元からある同種アイテムは残します。伐採数だけで収納成功とは言いません。葉の自然消滅後に遅れて落ちる全アイテムを回収する保証はありません。

チェスト満杯・消失・アクセス不能・部分収納・切断では投棄せず、状態を `node-bot/var/wood/state.json`（起動directoryがnode-botの場合）へ残します。ファイルはgit対象外です。再起動時に自動で伐採を再開しません。`!wood return` は現在の所持品差分を再計算し、格納済み数量を再び預けません。死亡・紛失などで開始時所持品が減った場合は自動収納を止めます。手動確認後に記録を解除してください。ワールド交換、巻戻し、サーバー移行時には古い登録を流用せず再登録します。

名前・NBT・追加componentなど特殊データ付きの収集対象アイテムが所持品にある場合も、通常アイテムとの取り違えを避けるため開始・収納を拒否します。手動で整理してから操作してください。

## APIと診断
認証付き `POST /v1/forestry/check` は `bot, x, y, z, grant` を受け、`allowed, reason, logs` を返します。座標はオンラインBotと同じworldとして解釈し、未ロードのchunkを生成しません。`grant=true` は最上段の原木に10秒・一回限りの破壊許可を発行します。`{bot, release:true}` は作業後の制御解除です。最大本文512bytes。Paper APIはschedulerのmain thread境界で実行します。

Nodeの `WoodCollection` は段階・固定失敗理由のみをログへ出し、対象名・座標・チャット・認証値は出しません。主な段階はsearching/harvesting/returning/depositing/blocked/idleです。状態ファイルは拠点位置と所持品を含むprivateデータです。

## 検証境界
Nodeのfake-world契約テストとPaperの単体テストで、正常系・拒否・世界変化・部分収納・死亡・停止を検証します。実際の成長イベント、サーバーの権限、掘削、拾得、収納、Minecraftチャット表示は別途承認した実ワールド試験が必要です。テスト成功だけを実運用での安全性・到達成功の証拠にはしません。
