# Minecraft コンパニオンの製品目標像

この文書は、Issue #184 で扱う Minecraft ボットの製品目標を定義する正本です。現行コードの説明ではなく、実装済みの範囲、目標、未検証の範囲を分けて記録します。

## 1. 製品の役割

ボットは、プレイヤーから受け取った言葉と Minecraft 内で観測できる状態をもとに、状況を理解し、目的に沿った計画を立て、安全を確認しながら行動し、行動後の結果を判断します。中心となるループは次のとおりです。

```text
チャット / ゲームイベント
  → 局所観測と記憶の検索
  → 目的・制約・安全条件を含む計画
  → Mineflayer / Paper への行動
  → 結果と危険の再観測
  → エピソード記憶・空間記憶の更新
```

「人間のような記憶」は意識や人格の再現を意味しません。時刻、場所、観測事実、行動、結果を結び付け、後の判断で「どこで、何を見て、何をしたか」を思い出せる振る舞いを目標にします。

## 2. 認知モデル

各情報には、取得元と確度を付けます。ゲームから直接提供された座標やブロック状態、チャットイベント、ボット自身の観測、モデルによる推論を同じ種類の事実として扱いません。

| 認知の入口 | 目標とする情報 | 現在確認できる範囲 |
| --- | --- | --- |
| 視覚・視野情報 | 将来的な実際の画面/視野に含まれる地形、バイオーム、樹木・丸石などの分布、明るさ、障害物、エンティティ | 現在は Mineflayer の座標・ブロック API と Entity 情報による局所スナップショットのみ。画面/視野情報、バイオームや資源分布の定期記録は未実装 |
| 聴覚・音イベント | ゲーム音と、その発生時点・方向、チャット、近傍イベント、危険通知を時系列で扱う | チャットの話者名・本文と AgentBridge 系イベント。ゲーム音の取得、発生時点の記録、方向/定位は未実装 |
| 記憶 | 座標・ディメンション・時刻に結び付く客観的局所観測、行動と結果、再利用可能なエピソード | オンメモリ KV、上限付き `perception_snapshots`、永続 Reflexion ログ。長期のエピソード/空間記憶は未実装 |

モデルが「危険そうだ」「木がありそうだ」と判断した場合、それは推論として記録し、直接観測した事実と混ぜません。未取得の情報を記憶へ補完してはいけません。

画面/視野や音をどのAPI・センサー・モデルで取得するかは、今後の検証で決める実装事項です。この目標像は知覚したい情報と provenance の境界を定義し、特定の取得方式を前提にしません。

## 3. 局所観測と記憶

定期観測は、ボットの現在位置を原点に、対象範囲と取得時点を固定して行います。観測レコードは少なくとも次の情報を持つことを目標にします。

- `observed_at`: 観測時刻
- `dimension` と `origin`: ディメンション、観測時点の X/Y/Z
- `window`: 半径・高さなどの観測範囲
- `facts`: 地形、バイオーム、ブロック分布、照明、天候、エンティティ、危険状態
- `provenance`: ゲーム API、Mineflayer、Paper イベント、チャットなどの取得元
- `episode`: その観測に結び付いた目的、行動、結果、失敗、再計画

検索時は現在地と目的に近い記憶を優先し、古い観測、ディメンション違い、移動や建築で変化した可能性がある情報をそのまま現在事実として使いません。再開時や危険判断の前には、位置、インベントリ、周辺ブロック、保護領域、接続状態を再観測します。

## 4. 「こっち来い」の合流契約

「こっち来い」「ここに来て」などの指示は、一般的な座標移動とは異なり、チャットを送ったプレイヤーへの合流として扱います。

1. Node 側のチャットイベントから話者を識別し、Python の計画コンテキストへ引き渡す。
2. 近距離で Mineflayer の `players` に有効なプレイヤー Entity が得られる場合は、その座標を使う。遠距離などローカル Entity が未観測のときは、認証付き Paper AgentBridge の `/v1/players/position` へ話者名を完全一致で照会し、Minecraft サーバーが保持するオンラインプレイヤーの位置スナップショットを取得する。いずれも許可されたゲーム内の座標データである。
3. その座標を視覚や聴覚から推測したものとして扱わない。取得元、取得時刻、ディメンションを保持し、欠損・古さ・不一致を検出する。
4. 合流前と移動中に、ボットの位置、敵対 Mob、液体・落下、明るさ、体力・満腹度、経路の歩行可能性を再確認する。
5. 話者が移動する場合は位置を再解決する。遠距離の合流は最大 16 区間、各区間最大 16 ブロック（合計約 256 ブロック）に制限し、上限を超えた場合は `rendezvous_distance_limit` で停止する。安全な経路がない、話者が消えた、ディメンションが違う、危険度が上がった場合も停止し、理由と次の選択肢を一度だけ伝える。既定の座標へ黙って退避してはいけない。
6. 到達判定は安全な近傍への到着と最新の観測で確認し、成功をチャットで報告する。

この座標照会は今回のゲーム内機能として許可されたデータ源です。プレイヤーの位置を、画像認識や音の方向推定で得たと説明してはいけません。

## 5. 現状・目標・未検証範囲

| 領域 | 現状 | 目標 / 未検証 |
| --- | --- | --- |
| 話者の引き渡し | チャットの `username` と本文を Node から Python へ渡し、`last_requester` に保存する経路がある | セッション、同名、切断、話者変更を含む契約の固定と実ゲーム確認 |
| 話者への移動 | Python 側の `move_to_player` 分岐に加え、Node 側の `followPlayer` 受理・Entity の完全一致解決、Entity 未観測時の認証付き Paper Bridge 位置照会、最大 16 区間×16 ブロック（約 256 ブロック）の有界 waypoint、区間ごとの位置再照会、安全エラー停止の経路がある。合流では掘削 fallback を使わず、Java/Paper・Node・Python の対象テストは通過している | `rendezvous_distance_limit` を含む固定エラーで上限・危険・照会不能を停止するが、実ゲームでの到達・サーバー間の端到端挙動は未実施。どこからでも必ず到達する機能とは扱わない |
| 周辺知覚 | Mineflayer の座標・ブロック API から位置、天候、時刻、照明、エンティティ、いくつかの危険状態を定期間隔で共有する | 実際の画面/視野情報、地形・バイオーム・樹木/丸石分布、ゲーム音の発生時点・方向、イベントの時系列化 |
| 記憶 | 最新の知覚履歴と Reflexion の失敗記録を計画へ渡す | 座標・時刻付きの客観的局所観測をエピソード/空間記憶として蓄積し、検索・陳腐化・矛盾を扱う |
| 判断 | pathfinder、照明・危険・体力等の一部の警告がある | 観測の provenance を保った安全評価、停止、再観測、再計画の一貫した契約 |

テスト用スタブが成功しても、Node、Paper、Minecraft サーバーを含む実ゲーム挙動の証明にはなりません。実装済みと記載する場合は、対応する契約テストと、必要な範囲の実環境証跡を併記します。

## 6. 非目標と境界

- 未取得のワールド全体を知っているように振る舞うこと。
- モデルの推論を、ゲームから直接得た観測事実として保存すること。
- プレイヤー識別子、チャット全文、精密な位置、内部ログを公開文書へ残すこと。
- 実ゲーム操作の許可なしに、サーバーやワールドへ接続・移動すること。
- この文書だけで画像・音声センサー、長期記憶、Node/Python の公開契約が実装済みだと扱うこと。
